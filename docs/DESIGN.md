# JP Surge Radar v2 — 設計

## 原則

1. **予測は現在から未来へ。** 過去を再構成した予測・教師データは作らない。
2. **判定**: 予測時点の基準終値から、翌営業日以降 **10 営業日以内の場中高値が +20%** に
   届けば成功、届かなければ失敗。予兆のない IR で動いた場合も区別せず数える。
3. **分析は 3000 円以下の全銘柄**。ただし記録・追跡するのは候補として出した銘柄だけ。
4. **候補は Claude が選ぶ**。1 日 10 銘柄前後、良いものが少なければ 5 銘柄程度。
   手順は `procedures/select.md`。
5. **教師データ = 自分が出した候補とその成否**。これを見て選び方を改善する。
6. **全銘柄にラベルを付ける**。チャート形状・出来高は決め打ちの定義で機械的に、
   材料(ニュース見出し)は Claude がその日に読んで付ける。ラベルは後から付け直さない。
7. **開始日以降のデータしか使わない。** 価格は開始時点の直近 10 営業日分だけを残し、
   以降は毎日積み上げる。材料も同じ窓から。
8. **ルールや閾値を過去データへの当てはめで決めない。** ラベルの定義は事前に決めて固定し、
   変えるときは日付と理由を残す。

## 日次の流れ(平日、引け後)

| 順 | 処理 | 担当 |
|---|---|---|
| 1 | 全銘柄の日足を取得 | `scripts/daily_data.py` |
| 2 | 3000 円以下の全銘柄の特徴量とチャート・出来高ラベルを計算して保存 | 同上 |
| 3 | 全銘柄のニュース見出しを取得して保存 | 同上 |
| 4 | 追跡中の候補の成否を更新 | 同上 |
| 5 | 新しい見出しにラベルを付ける | Claude (`procedures/label.md`) |
| 6 | 自分の過去の候補の成否を振り返る | Claude (`procedures/select.md`) |
| 7 | 候補を 5〜10 銘柄選んで記録 | Claude (`procedures/select.md`) |

クラスタリング(教師なし)は、開始日以降に積み上がったスナップショットとラベルだけを使う。

## テーブル

| テーブル | 中身 |
|---|---|
| `securities` | 銘柄台帳(コード・社名・市場) |
| `prices` | 日足 |
| `snapshots` | 日付×銘柄の特徴量とチャート・出来高ラベル(3000 円以下の全銘柄) |
| `news` | 見出し(銘柄・日付・配信元・URL) |
| `news_labels` | 見出しへの Claude のラベル(ラベル付け日時・手順書の版つき) |
| `candidates` | Claude が出した候補(基準日・基準終値・理由・ラベル) |
| `outcomes` | 候補の追跡結果(最高値・到達日・成否) |
| `runs` | 日次処理の実行記録 |
